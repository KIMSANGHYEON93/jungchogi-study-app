# 생성 문항 검수 절차 (Phase 4)

> 대상: `public/data/generated/<source>.json`
> 관련: `claudedocs/BLUEPRINT.md` §4.4 · §5 Phase 4 · `scripts/generate-variants.mjs`

---

## 0. 왜 사람이 봐야 하는가

`scripts/validate-generated.mjs` 는 **형식만** 본다. 필드가 다 있는지, id 가 겹치지 않는지,
`variantOf` 가 실존하는 원본을 가리키는지. **정답이 실제로 맞는지는 기계가 모른다.**

`reviewed: false` 인 파일을 앱이 쓰지 않는 이유가 그것이다. 틀린 정답으로 공부하면
공부하지 않은 것보다 나쁘다.

| 누가 | 무엇을 |
|---|---|
| `validate-generated.mjs` (자동, CI) | 필드 유무·타입·빈 값, id 중복, 원본 id 충돌, `variantOf` 실존, `id = <variantOf>-v<n>`, 드릴 `lang` 이 허용값이고 원본과 같은지 |
| **사람 (이 문서)** | 정답이 맞는지, 원본과 겹치지 않는지, 난이도가 튀지 않는지, 지문이 애매하지 않은지, 한국어가 자연스러운지 |

---

## 1. 검수 전 준비

```bash
node scripts/validate-generated.mjs
```

`❌` 가 하나라도 나오면 **검수를 시작하지 않는다.** 형식이 깨진 파일은 다시 생성하거나
손으로 고친 뒤 다시 돌린다. `✅` 와 `(미검수 — 앱이 사용하지 않음)` 이 떠야 다음 단계다.

---

## 2. 항목마다 볼 것 (다섯 가지)

문항 하나씩, 원본(`variantOf` 가 가리키는 문항)과 나란히 놓고 본다.

### ① 정답이 맞는가 — **가장 중요**

- **단답형·보강**: 변형 지문이 묻는 것과 `answer` 가 실제로 대응하는가.
  교재(`public/data/정처기_Day*.md`)에서 근거를 찾을 수 있는가.
  교재에 없는 용어·수치를 지어냈다면 그 항목은 버린다.
- **코드트레이싱**: `code` 를 **직접 실행하거나 손으로 추적해** `expectedOutput` 과 맞춰 본다.
  - C/Java/Python 은 실행이 제일 빠르고 확실하다.
  - SQL 은 `context` 의 예제 테이블로 결과를 손으로 계산한다.
  - `answer` 의 추적표가 `expectedOutput` 과 일관되는가. 추적표 중간이 틀렸는데 결과만
    맞는 경우가 있다 — 그런 항목은 학습자를 잘못 가르친다.

> 실행해서 확인한 항목은 그 자리에서 `expectedOutput` 을 실행 결과로 맞춰 고쳐도 된다.
> 다만 `answer` 의 추적표도 함께 고쳐야 한다.

### ② 코드가 실제로 도는가 (드릴만)

선언 누락, `import`/`#include` 누락, 세미콜론, SQL 문법. 안 도는 코드는 문항이 아니다.

### ③ 원본과 겹치지 않는가

- 지문이 원본과 글자 그대로 같거나, 낱말 몇 개만 바뀐 수준이면 뺀다.
- 같은 원본의 변형끼리도 서로 겹치면 하나만 남긴다
  (`--variants 3` 이면 세 개가 서로 다른 각도여야 한다).
- 정답이 원본과 똑같다면 **지문을 잘못 바꾼 것**이다. 개념만 같고 답은 달라야 정상이다.
  (예외: 같은 개념을 다른 각도로 물어 답이 같아지는 경우는 있다. 그때는 지문이
  충분히 달라 학습 효과가 있는지로 판단한다.)

### ④ 난이도가 튀지 않는가

원본이 1단계 추론이면 변형도 1단계여야 한다. 변수를 셋 더 넣어 추적 20단계가 된
드릴이나, 원본보다 훨씬 쉬워 그냥 외운 것만 물어보는 단답형은 뺀다.

### ⑤ 답이 하나로 정해지는가

"~에 대해 설명하시오" 처럼 채점 기준이 안 서는 지문, 여러 답이 다 맞는 지문은 뺀다.
Phase 3 의 자동 채점이 그런 문항에서 `confidence` 를 낮게 주고 자기 채점으로 떨어진다 —
그럴 바에는 문항을 빼는 게 낫다.

## 3. 판정과 반영

| 판정 | 무엇을 | 어떻게 |
|---|---|---|
| 통과 | 다섯 항목 모두 문제 없음 | 그대로 둔다 |
| 수정 | 정답·출력·오타 정도의 국소 결함 | 손으로 고치고, 고친 내용을 커밋 메시지에 남긴다 |
| 폐기 | 정답이 틀렸는데 못 고침 / 원본과 겹침 / 난이도가 튐 | `items` 에서 **항목을 통째로 지운다** (`id` 를 비우거나 빈 문자열로 두지 않는다 — 검증기가 잡는다) |

폐기가 절반을 넘으면 문항이 아니라 **프롬프트가 문제**다. `lib/ai/variants.js` 의
`COMMON_RULES`·변형 각도를 손보고 다시 생성한다.

## 4. `reviewed: true` 로 올리기

전체 항목을 다 본 뒤에만 올린다. 일부만 보고 올리면 안 본 항목이 그대로 학습자에게 나간다.

```jsonc
{
  "version": 1,
  "source": "quiz100",
  "generatedAt": "...",
  "model": "claude-opus-5",
  "reviewed": true,        // ← 여기만 손으로 바꾼다
  "items": [ ... ]
}
```

바꾼 뒤 다시 검증하고 커밋한다.

```bash
node scripts/validate-generated.mjs
npm test
git add public/data/generated/<source>.json
git commit
```

커밋 메시지에 남길 것:

- 검수한 항목 수 / 폐기한 항목 수와 그 이유
- 코드 드릴이면 **어떻게 확인했는지** (실행 / 손 추적)
- 검수자와 검수일

---

## 5. 되돌리기

검수 후에 틀린 항목이 발견되면 **파일 전체를 `reviewed: false` 로 내린다.**
항목 하나만 지우고 `true` 를 유지하면, 같은 검수 회차의 나머지 항목도 못 믿을 이유가
생겼는데 계속 쓰게 된다. 내리고 → 고치고 → 다시 전체를 본다.

---

## 6. 프론트엔드와의 계약

- 앱은 `reviewed === true` 인 파일만 읽는다. `false` 면 **원본 문항만** 쓴다.
- 앱은 `version` 이 `1` 이 아니면 무시한다.
- 생성 문항은 항목의 `generated: true` 로 구별할 수 있다 — 화면에서 "AI 생성" 표시를
  붙이거나 학습자가 껐다 켤 수 있게 한다.
- 파일이 없는 것은 정상이다 (404 를 오류로 다루지 않는다).
